## 2026-09-18 - [CRITICAL] Fix Server-Side Request Forgery (SSRF) in webhooks
**Vulnerability:** The webhooks functionality in `server/app.mjs` was vulnerable to Server-Side Request Forgery (SSRF). The `sendWebhook` function used `fetch` to send HTTP requests to user-provided URLs without validating the resolved IP address, and the webhook creation endpoint (`POST /api/orgs/:id/webhooks`) only validated that the URL started with `http://` or `https://`.
**Learning:** This existed because standard URL validation regexes do not account for DNS resolution pointing to internal subnets (e.g., `127.0.0.1`, `10.0.0.0/8`, `169.254.169.254`), and `fetch` natively follows redirects by default, allowing attackers to bypass simple validation with a malicious server returning a 301 redirect to an internal IP. Additionally, dual-stack environments require both IPv4 and IPv6 resolution to prevent bypasses.
**Prevention:** To avoid this next time, always resolve hostnames using `node:dns/promises` (`resolve4` and `resolve6`) before making outbound requests to user-controlled URLs. Use `node:net`'s `BlockList` to check the resolved IPs against private/internal subnets (including `::ffff:0:0/96` for IPv4-mapped IPv6). Finally, always disable automatic redirects in `fetch` (`redirect: 'error'`) to prevent open-redirect SSRF bypasses.
